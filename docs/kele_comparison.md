# KELE 与本项目的关系

本文用于说明 KELE 论文和本项目的关系：KELE 是一个重要的 Socratic tutoring 参考框架，但本项目不复刻 KELE。本项目定位为中文初中数学 Graph-grounded Adaptive Tutor Agent，核心问题是如何把数学知识、学生步骤判定、原题主线和自适应教学组织成一个稳定的教学工作流。

## 1. KELE 的核心思路

KELE 关注的是让大语言模型更像“会追问、会引导、会组织教学过程”的苏格拉底式教师。它不是只让模型回答问题，而是把教学对话拆成可控制的阶段、策略、角色分工、数据集和评估维度。

### 1.1 SocRule 五阶段

KELE 用 SocRule 把苏格拉底式教学过程拆成五个阶段。可以理解为：先定位学生当前认知状态，再选择合适的追问或提示方式，通过逐步引导让学生自己推进理解，最后总结或巩固学习结果。

这类阶段设计的价值在于：它把“不要直接给答案”从一句泛泛的 prompt，变成可执行的教学流程。模型在不同阶段承担不同任务，例如诊断、追问、提示、反馈、总结，而不是每轮都自由发挥。

### 1.2 34 种教学策略

KELE 进一步把教师在对话中的动作拆成 34 种教学策略。这些策略覆盖了苏格拉底式教学中常见的微动作，例如澄清问题、追问理由、要求举例、指出矛盾、提示前置知识、鼓励学生反思、总结当前结论等。

它的重点不是“策略数量多”，而是把教师话语从自然语言风格变成一个可选择、可标注、可评估的 action taxonomy。这样系统可以先决定“这一轮应该做什么教学动作”，再生成具体表达。

### 1.3 consultant-teacher 双 Agent

KELE 使用 consultant-teacher 双 Agent 分工：consultant 更像教学顾问或策略规划器，负责分析对话状态、判断学生理解、选择教学阶段和策略；teacher 则负责把策略转化为面向学生的自然语言回复。

这个分工的意义是降低单个模型同时承担“诊断、规划、表达、控场”的负担。consultant 偏决策，teacher 偏生成，系统因此更容易约束、审计和评估。

### 1.4 SocratDataset

KELE 构建 SocratDataset，用来承载苏格拉底式教学对话样本、阶段标注和策略标注。数据集的作用不只是训练模型，也提供了一个分析框架：什么样的教师话语算作有效引导，什么样的对话推进符合苏格拉底式教学。

对研究系统来说，SocratDataset 的价值在于把“好教学对话”具体化，便于比较不同模型或不同 agent 架构在教学过程中的表现。

### 1.5 9 维教学质量评估

KELE 用 9 个维度评估教学质量，强调不能只看回答是否流畅，也要看它是否符合教学目标、是否阶段合适、是否策略合理、是否真正引导学生思考。概括来说，这类评估关注：内容正确性、目标相关性、阶段匹配、策略适配、启发性、互动性、连贯性、个性化、表达质量与安全边界。

这对本项目很重要：教育 agent 的质量不应只用“答案对不对”衡量，还要评估是否过早泄露答案、是否围绕原题、是否只问一个有效问题、是否承认学生正确步骤、是否能针对学生掌握度调整深浅。

## 2. 本项目不复刻 KELE

本项目不是 KELE 的中文复现，也不是一个通用 Socratic dialogue chatbot。本项目的定位是：中文初中数学 Graph-grounded Adaptive Tutor Agent。

也就是说，本项目的中心不是复刻 SocRule、34 种策略或双 Agent 论文结构，而是研究“确定性数学规则 + Graph/Textbook RAG + LLM 生成 + 学生掌握度更新”如何共同构成一个稳定的数学辅导系统。

当前 MVP 聚焦一元一次方程。系统采用六节点 LangGraph 工作流：

```text
diagnose -> retrieve -> teaching_policy -> teach -> memory_update -> log
```

这个工作流和 KELE 有相似的“先诊断、再选教学动作、再生成回复”的思想，但本项目的 grounding 重点更强：学生步骤由数学 checker 判定，教学回复必须锚定 original_problem，检索内容不能污染原题主线。

## 3. 本项目与 KELE 的关键区别

### 3.1 本项目有 math_checker，可检查学生数学步骤

KELE 的重点是苏格拉底式教学过程和话语策略；本项目额外引入 `app/agent/math_checker.py`，用 `Fraction` 精确解析和判定一元一次方程。

学生给出单步、中间式、多步计划或最终答案时，对错判定必须经过 math_checker。LLM 不能自由裁决学生数学步骤，也不能在 teach 阶段推翻 checker 结论。这是本项目区别于纯对话式 Socratic tutor 的关键安全边界。

### 3.2 本项目有 original_problem 锚定，防止跑题

本项目把学生首轮给出的题目保存为 `original_problem` / `target_equation`。后续每轮教学都必须围绕这道原题推进，除非教学动作明确允许使用类比例题或变式题。

这个机制解决了教育 LLM 常见问题：检索到的例题、模型自己编的新题、或 prompt 中的示例题污染主线。对数学辅导来说，学生问的是手上的那道题，系统必须始终知道“我们正在解哪一道题”。

### 3.3 本项目支持学生多步回答

本项目不强制学生一步一答。学生可以说“先都减四，然后同时除以3”，也可以直接写 `3x=3，然后 x=1`，系统会整体模拟这些步骤并判断是否正确。

这点和简单 Socratic prompting 很不一样：苏格拉底式引导不等于机械地阻止学生跳步。只要学生的多步计划数学上正确，系统应整体认可，而不是把学生拉回已经回答过的第一步。

### 3.4 本项目有 student memory / mastery tracking

本项目维护学生在不同知识点上的掌握度，记录尝试次数、掌握度变化和常见误解。掌握度会影响讲解深浅、提示粒度、复习建议和变式题推荐。

但 memory 只是软约束，不能覆盖 math_checker。即使学生掌握度低，只要多步计划正确，系统也必须认可；不能因为 mastery 低就强制一步一答。

### 3.5 本项目计划接入 Graph RAG / Textbook RAG / Math23K / Ape210K

本项目当前使用本地 JSON mock Graph RAG，但接口目标是未来平滑替换为真实知识图谱与教材检索：

- Graph RAG：用于知识点依赖、前置概念、章节结构和学习路径。
- Textbook RAG：用于教材解释、例题、相似练习和常见误解。
- Math23K / Ape210K：用于扩充数学题库，尤其是一元一次方程相关练习与变式题。

因此，本项目的研究重点是数学知识 grounding，而不是只优化苏格拉底式对话风格。

### 3.6 本项目重点是数学知识 grounding，而不是单纯 Socratic dialogue style

KELE 更强调如何让 LLM 进行苏格拉底式教学对话；本项目更强调数学任务中的可靠性：题目是否保持一致，学生步骤是否同解，是否过早泄露最终答案，检索内容是否污染原题，掌握度是否只作为教学深浅信号。

换句话说，KELE 主要回答“怎样组织苏格拉底式教学对话”；本项目主要回答“怎样让一个中文初中数学 tutor 在有知识 grounding 和数学规则约束的情况下稳定教学”。

## 4. 可以借鉴 KELE 的地方

### 4.1 教学阶段设计

本项目已经有六节点 workflow，但还可以借鉴 KELE 的阶段化思想，把每轮教学状态描述得更细。例如在 `teaching_policy` 中区分诊断、澄清、轻提示、强提示、反馈、总结、巩固等阶段，让策略选择更可解释。

### 4.2 consultant-teacher 分工

本项目现在的 `diagnose` 和 `teaching_policy` 已经承担了部分 consultant 职能，`teach` 节点承担 teacher 职能。未来可以更显式地把“教学顾问”和“表达教师”分离：前者输出结构化教学计划，后者只负责把计划转成学生可读的中文回复。

这样有助于减少 LLM 在最终回复中越权判题、跑题或改变教学目标的风险。

### 4.3 teaching action taxonomy

本项目已有 `TeachingAction`，包括诊断问题、概念解释、一级提示、二级提示、例题、练习、批改反馈和复习安排。可以参考 KELE 的 34 种教学策略，把当前 action taxonomy 扩展得更细，但扩展必须服务于数学 grounding，而不是为了复刻数量。

可优先补充的动作包括：要求学生解释理由、检查等式两边操作、让学生代回验证、指出同解性风险、提示前置概念、总结已完成步骤、针对常见误解给反例。

### 4.4 evaluation metrics

本项目已有 golden conversations 和确定性行为检查。可以借鉴 KELE 的多维评估，把现有评测从“是否违规”扩展到“教学质量画像”。

适合本项目的维度包括：数学正确性、原题锚定、步骤判定准确性、提示粒度、是否尊重学生多步回答、是否不过早泄露答案、是否单问句收尾、是否利用 mastery 调整深浅、是否正确使用检索证据。

## 5. 结论

KELE 是本项目的重要参照：它证明了教育 agent 需要阶段、策略、角色分工、数据集和多维评估，而不是只靠一个“请用苏格拉底式教学”的 prompt。

但本项目不应复刻 KELE。本项目的独特价值在于把苏格拉底式教学思想放进中文初中数学场景，并用 math_checker、original_problem 锚定、多步回答支持、student memory、Graph/Textbook RAG 和数学评测来保证 grounding。未来可以吸收 KELE 的教学阶段、双 Agent 分工、策略 taxonomy 和评估框架，但所有借鉴都应服务于数学知识 grounding 和稳定教学，而不是把系统改成通用 Socratic chatbot。
