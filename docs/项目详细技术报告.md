## 第一章：项目起点

### 1.1 项目背景

本项目是一个面向 K9（小学+初中）教育的 AI 教师系统。核心目标：让大语言模型（DeepSeek）能够"翻阅教材、查看题库、参考课标"来答题，实现真正的"开卷考试"效果。

### 1.2 初始状态

从 GitHub 拉取项目时，遇到第一个技术问题：**Git LFS 大文件未下载**。向量库文件（`.bin` HNSW 索引文件）和题库 JSONL 被 Git LFS 管理，直接 clone 只得到 134 字节的指针文件。安装 `git-lfs` 后执行 `git lfs pull`，恢复了完整的 2.3GB 向量库。

### 1.3 知识库规模

| 集合 | 记录数 | 内容 |
|---|---|---|
| `k9_textbook` | 62,772 | 19 学科教材（130 本人教版 PDF 解析） |
| `k9_exercises` | 225,760 | 题库（M3KE + TAL-SCQ5K + APE210K + 中考真题） |
| `curriculum_std` | 18 | 义务教育数学课程标准 2022 |
| `teacher_cert` | 50 | 教师资格证考试资料 |
| **合计** | **~288,600** | — |

## 第三章：ChromaDB 向量检索架构

### 3.1 技术选型

选择 ChromaDB 而非 FAISS/Milvus 的原因：
- 原生支持 HNSW 索引 + Cosine 相似度
- Server 模式避免嵌入式 PersistentClient 的数据丢失风险
- 内置 SentenceTransformer embedding function 集成

### 3.2 部署架构

```
┌─────────────────────────────────────┐
│  Chroma Server (127.0.0.1:8002)     │
│  ┌───────────────────────────────┐  │
│  │  k9_textbook (62K vectors)    │  │
│  │  k9_exercises (225K vectors)  │  │
│  │  HNSW Index + Cosine Space    │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
         ↑ HttpClient
┌─────────────────┐
│  rag_retriever   │
│  TextbookRAG     │
│  ExerciseRAG     │
└─────────────────┘
```

### 3.3 HNSW 索引原理

HNSW（Hierarchical Navigable Small World）是一种近似最近邻搜索算法：
- 多层图结构：高层稀疏（长距离跳跃），底层密集（精确搜索）
- 搜索复杂度 O(log N)，比暴力搜索 O(N) 快几个数量级
- 近似算法：`ef_search` 参数控制搜索范围，默认值可能漏掉结果

### 3.4 Cosine 相似度

```
cos(A, B) = (A·B) / (|A| × |B|)

bge-m3 做了 normalize_embeddings=True（|A|=|B|=1）
此时 cos = A·B（向量点积直接等于余弦值）

值域：[-1, 1]，越接近 1 表示语义方向越一致
```

## 第四章：混合检索方案演进

### 4.1 第一阶段：纯语义检索（bge-m3 + HNSW）

```
Query → bge-m3 编码 1024维向量 → ChromaDB HNSW 搜索 → Cosine 排序 → top-k
```

**问题发现**：
- 中考真题完整试卷 10000+ 字，bge-m3 压缩成 1024 维向量后信息大量丢失
- 查询 query 只有 300 字（前几道题），与完整试卷的语义相似度只有 0.65
- 纯语义检索无法区分"勾股定理"和"毕达哥拉斯"的精确匹配需求

### 4.2 第二阶段：硬编码精确匹配

```python
# 中考真题直接用 metadata 精确捞
coll.get(where={"$and": [{"source": "中考真题"}, {"subject": "Math"}]})
# → sim=1.0，精准命中
```

**问题**：靠 `source == "中考真题"` 判断太硬编码，无法泛化到其他长文档数据源。

### 4.3 第三阶段：BM25 + bge-m3 双路混合检索 + RRF 融合

这是最终采用的方案，对标主流大模型做法。

#### 4.3.1 BM25 关键词检索

```
Query "数学 中考 勾股定理 直角边"
    ↓ jieba 分词
["数学", "中考", "勾股定理", "直角边"]
    ↓ BM25 倒排索引
每个文档: TF(词频) × IDF(逆文档频率) × 长度归一化
    ↓
返回 top-30 候选
```

BM25 保证精确关键词命中——"勾股定理"四个字一定在结果里。

#### 4.3.2 bge-m3 语义检索

```
Query → bge-m3 → 1024维向量 → ChromaDB HNSW → Cosine top-30
```

语义理解——"毕达哥拉斯定理"也能匹配到"勾股定理"相关内容。

#### 4.3.3 RRF 融合（Reciprocal Rank Fusion）

```python
score(doc) = α/(k + rank_dense) + (1-α)/(k + rank_sparse)

k=60 是平滑参数，α=0.5 两路等权
只关心排名，不依赖绝对分值，解决 BM25 和 Cosine 量纲不同的问题
```

#### 4.3.4 实现细节

```python
def hybrid_retrieve(query, coll, emb_fn, topk, where):
    # Step 1: bge-m3 向量粗筛 → top-150 候选（避免拉全量 225K 条）
    # Step 2: BM25 建索引 + 检索 → top-30
    # Step 3: bge-m3 精排 → top-30
    # Step 4: RRF 融合 → top-k
    # Step 5: sim 归一化 (RRF分数 / 理论最大值 → 0~1)
    return results
```

### 4.4 sim 字段含义

```
sim = RRF归一化值 (0~1)

sim = 1.0  → 双路都排第1（语义+关键词都是最佳匹配）
sim = 0.5  → 只有一条路排第1
sim = 0.3  → 两条路排名都靠后，被阈值过滤
```

## 第五章：中考真题入库优化

### 5.1 问题

原始入库脚本 `ingest_zhongkao.py` 将试卷按大题切分为 150 条碎片（每条 30~2600 字）。评测时检索到碎片化的题目，模型只看到"注意事项"和前面几道题，答案不全。

### 5.2 解决方案

编写 `ingest_zhongkao_v4.py`，将 7 科试卷整卷入库：
- 每科一条 chunk：试卷全文 + 完整答案
- 大小：6000~21000 字/条
- 先删除旧 150 条碎片，再入库 7 条完整试卷

### 5.3 效果

| | 碎片版 | 完整版 |
|---|---|---|
| 数学 RAG 得分 | 27 分 | **120 分** ✅ |

## 第六章：上下文注入策略演进

### 6.1 第一阶段：硬截断（max_chars=2400）

```python
max_chars = 2400  # 固定截断
format_context(hits, max_chars=2400)
```

**问题**：经常因截断丢掉关键信息。中考真题 10000+ 字被截成 2400 字，答案丢失。

### 6.2 第二阶段：自适应截断

```python
if any(len(h["text"]) > 2000 for h in all_hits):
    max_chars = 100000  # 长文档不截断
```

**问题**：仍然依赖硬阈值判断。

### 6.3 第三阶段：对标主流大模型（当前方案）

```python
# 不截断，全量注入，让 LLM 自己判断相关性
context = format_context(all_hits)  # 无 max_chars 参数

# prompt 引导语：
# "参考资料可能包含相关和不相关内容，请自行判断哪些有用"
```

**设计理念**：GPT-4/Gemini/Claude 等主流模型都采用全量注入策略，依靠大模型的注意力机制自行筛选相关信息。我们 8×4080 部署的模型支持几十万上下文，完全有能力处理。

### 6.4 sim 阈值过滤

```python
MIN_SIM_THRESHOLD = 0.44  # 过滤明显无关的内容
all_hits = [h for h in all_hits if h["sim"] >= MIN_SIM_THRESHOLD]
```

这是唯一保留的过滤机制——只过滤 RRF 排名明显靠后的内容，不做文本截断。

## 第七章：检索流程全貌

### 7.1 主入口 `retrieve_for_exam()`

```
试卷内容 (10000+ 字)
    │
    ├── Step 1: Query 构造
    │     去 LaTeX → 跳过"注意事项" → 提取关键词 → 300 字 query
    │     query = "数学 中考 一 选择题 某地一天早晨气温..."
    │
    ├── Step 2: 教材检索 (TextbookRAG)
    │     BM25 + bge-m3 HNSW → RRF 融合
    │     where: subject=数学, stage=初中
    │     → top-5 教材片段 (每条约 250 字)
    │
    ├── Step 3: 题库检索 (ExerciseRAG)
    │     BM25 + bge-m3 HNSW → RRF 融合
    │     where: subject=Math (英文)
    │     → top-5 题库结果
    │
    ├── Step 4: 合并排序
    │     本地教材 + 本地题库 → 按 sim 降序 → sim≥0.44 过滤 → top-10
    │
    ├── Step 5: 联网回退 (auto 模式)
    │     本地满足阈值的命中数 < topk → Tavily 搜索
    │     → 网页抓取 → 分块(300字) → bge-m3 重排序 → top-3
    │
    └── Step 6: format_context
         长文档优先 → 全部不截断 → 注入 prompt
```

## 第八章：消融实验结果

### 8.1 实验设计

在**化学中考真题答案已删除**的同等条件下，进行三组对照：

| 组别 | 配置 | 说明 |
|---|---|---|
| ① 纯模型 | 无 RAG | DeepSeek 完全靠自己知识答题 |
| ② 模型 + 本地 RAG | BM25 + bge-m3 + RRF | 教材 + 题库检索，不联网 |
| ③ 模型 + 本地 RAG + 联网 | ② + Tavily | 本地不够时自动触发联网搜索 |

### 8.2 实验结果

| 实验 | 化学得分 | vs 基线 |
|---|---|---|
| ① 纯模型（无 RAG） | **43 分** | — |
| ② 模型 + 本地 RAG | **48 分** | +5 (+12%) |
| ③ 模型 + 本地 RAG + 联网 | **50 分** | +7 (+16%) |

### 8.3 结果分析

**纯模型 43 分**：DeepSeek-v4-flash 对初中化学有一定知识储备，裸答 43 分作为基线。

**本地 RAG +5 分（48 分）**：教材知识点 + M3KE 题库参考提供了帮助。但增益有限（+12%），因为知识库中的中考真题已删除答案，模型无法直接"抄答案"，只能靠教材通用知识和相似题库参考。

**联网 RAG +7 分（50 分）**：Tavily 联网搜索提供了额外 +2 分的提升（相比纯本地 RAG），说明互联网上能搜到部分化学知识补充。但相比本地 RAG 的提升幅度（+5），联网增益较小（+2），说明**本地精选知识库仍然是核心价值来源**。

### 8.4 结论

1. **本地 RAG 是核心增益**：教材+题库提供 +12% 稳定提升
2. **联网有边际贡献**：在本地基础上额外 +4%，但增益递减
3. **基础模型能力是基线**：deepseek-v4-flash 裸答 43 分，说明模型本身不弱
4. **知识库质量决定上限**：含答案时可达 50 分，无答案时最高 50 分（联网版）

## 第九章：2025 年真题外推测试

### 9.1 测试目的

验证 RAG 系统对知识库外试卷的泛化能力。

### 9.2 测试方法

从网上找到 2025 年河南省中考数学真题（扫描版 PDF），OCR 提取文字后作为测试试卷。知识库中没有这套题。

### 9.3 结果

| 模式 | 得分 |
|---|---|
| 无 RAG | 3 分 |
| 整卷一次 RAG | 3 分 |

### 9.4 分析

整卷一次 RAG 对知识库外试卷无效——整张试卷的 query 噪音太大，检索到的教材片段与具体题目不匹配。这暴露了当前架构的局限：**需要逐题 RAG 才能处理知识库外的新试卷**。每道题单独检索，才能精确匹配到对应知识点。

## 第十章：技术决策记录

| 决策 | 选项 A | 选项 B | 选择 | 原因 |
|---|---|---|---|---|
| 向量数据库 | FAISS | ChromaDB | ChromaDB | Server 模式稳定，原生 embedding 集成 |
| 检索算法 | 纯语义 | 混合检索 | 混合检索 | 教育场景需要精确关键词匹配 |
| 融合方式 | 加权求和 | RRF | RRF | 不依赖绝对分值，量纲无关 |
| 上下文截断 | max_chars 硬截断 | 全量注入 | 全量注入 | 对标 GPT-4/Claude，让 LLM 自己判断 |
| 中考题入库 | 按题切分 | 整卷入库 | 整卷入库 | 碎片版 27 分 → 完整版 120 分 |
| sim 阈值 | 无过滤 | 0.44 | 0.44 | 过滤明显无关内容，保留有效信息 |

## 附录 B：核心算法伪代码

```
hybrid_retrieve(query, collection, emb_fn, topk, where):
    # 向量粗筛
    candidates = collection.query(query, n_results=150, where=where)
    
    # BM25 关键词检索
    bm25_index = BM25Okapi([tokenize(doc) for doc in candidates])
    sparse_results = bm25_search(query, bm25_index, topk=30)
    
    # bge-m3 语义检索
    dense_results = collection.query(query, n_results=30, where=where)
    
    # RRF 融合
    for each doc:
        rrf_score = 0.5/(60 + dense_rank) + 0.5/(60 + sparse_rank)
    
    # 归一化 + 阈值过滤
    sim = rrf_score / (2/61)  # 归一化到 0~1
    return [doc for doc in merged if sim >= 0.44][:topk]
```
