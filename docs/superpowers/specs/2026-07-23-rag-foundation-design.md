# 物理试卷文本 RAG 基础修复设计

日期：2026-07-23

## 目标

先修复 `llm-test` 中本地文本 RAG 的基础检索能力，再评估它对整卷答题的影响。第一阶段只覆盖初中物理教材和题库，不改联网、Oracle、图片理解及正式 Teacher Agent 工作流。

首要验收指标是：在 30–50 道人工标注的物理题上，相关教材片段的 Recall@5 不低于 80%。达到该门槛后，再运行无 RAG 与本地 RAG 的整卷对照实验；整卷得分是观察指标，不作为检索基础修复的唯一判据。

## 当前问题

1. BM25 只在向量检索先选出的候选中运行，不是独立稀疏召回，无法补救向量漏召回。
2. RRF 排名分数与绝对相关度混用；第一名即使不相关，也可能得到看似很高的归一化分数。
3. 查询清洗会删除 LaTeX 公式，损失物理量、数值关系和单位等关键线索。
4. 逐题检索只取一条结果，且最终上下文按整卷顺序硬截断到 16000 字，后部题目可能没有上下文预算。
5. 教材元数据存在空章节、通用标题和 OCR 乱码；当前缺少明确的质量过滤与可诊断日志。
6. 没有人工相关性标注集，阈值和权重只能凭直觉调整，无法判断改动是否真正提升召回。

## 方案选择

采用“两阶段、失败驱动”的方案：

1. 先建立可重复评测集并修正查询、独立召回、融合、门控和上下文预算。
2. 分析 Recall@5 失败样本；只有证据表明原始 chunk 本身不可检索时，才针对失败章节调整分块和重建索引。

不选择仅修改几个阈值的最小补丁，因为它不能解决 BM25 假独立、公式丢失和上下文饥饿。不立即全量重建知识库，因为尚无失败样本证明哪些分块规则需要改变。

## 数据与标注集

新增 JSONL 格式的物理检索基准，每条至少包含：

- `question_id`：稳定题号或样本 ID。
- `question`：单题完整文本，保留公式、单位和图片占位说明。
- `subject`：固定为“物理”。
- `relevant_docs`：一个或多个稳定文档标识，优先使用 Chroma ID；若现有数据无稳定 ID，则使用来源文件、chunk 序号与内容摘要组成的复合标识。
- `relevance_note`：人工说明该片段为什么相关，便于复核。

样本从当前物理试卷中选取 30–50 题或小问，覆盖选择、填空、作图、实验、计算以及不同章节。答案只用于人工判断知识点和相关片段，不进入检索 query，也不注入模型。

评测脚本输出 Recall@1、Recall@5、MRR、无命中题目及其前五候选，结果保存为带时间戳的 JSON/Markdown，确保每次调参可比较。

## 检索架构

### 查询构造

为每道题生成两个视图：

- 语义查询：去除 Markdown 装饰和模板噪声，但保留公式内容、数值、单位、物理量名称及题干条件。
- 稀疏查询：使用 jieba 中文词、英文符号、数字和单位 token，避免把公式整体删除。

不使用答案扩写查询。图片在本阶段只保留替代文本或 URL 标记，不声称模型已理解图片内容。

### 独立双路召回

- 向量路：由 Chroma/BGE-M3 在指定学科和学段过滤条件下独立召回 Top50。
- BM25 路：从同一过滤范围的完整语料缓存建立索引，独立召回 Top50，不依赖向量候选。
- BM25 缓存以集合名、过滤条件和集合文档数量为键；数量变化时失效。语料通过分页读取，避免 SQLite/HTTP 参数过多。

两路结果必须携带稳定文档 ID、各自原始排名和原始分数，以便诊断。

### 候选融合与绝对相关度

先取两路候选并集，用 RRF 计算 `rank_score`，只用于候选排序。随后对并集中的候选统一计算 BGE-M3 查询—片段余弦相似度，得到 `relevance_score`。

最终排序默认以 `relevance_score` 为主、`rank_score` 为次级打破平局。注入门槛只读取 `relevance_score`，不再拿 RRF 归一化值冒充绝对相关度。具体阈值通过标注集扫描确定，并写入评测报告，而不是直接沿用 0.5 或 0.65。

第一版不引入新的 cross-encoder 模型，以控制显存和部署复杂度；如果 Recall@5 达标但 Top1/MRR 明显偏低，再单独评估 reranker。

### 质量过滤

候选在进入最终排名前执行保守过滤：

- 空文本和极短无信息文本直接丢弃。
- 对明显 OCR 乱码使用字符可读性比例过滤，但保留公式密集、数字密集片段。
- 空章节或通用标题不直接删除，只降低诊断质量标记，避免误删正文相关片段。
- 记录每条被过滤候选的原因，便于发现过滤过严。

### 逐题上下文预算

每题召回 Top5，满足标定阈值的结果中最多注入 Top2。上下文按题号组织，明确标注“第 N 题参考”，并采用逐题字符预算；单条过长片段截取与题目最相关的窗口。

整卷汇总时使用公平预算：先为每个有命中的题目保留第一条核心片段，再按相关度分配剩余预算。不得简单拼接后从尾部硬截断，从而保证后部题目不会天然吃亏。

保持现有 `retrieve_for_exam_questionwise()` 返回接口兼容；新增的结构化诊断数据通过内部对象或可选报告输出承载。

## 分块改进的触发条件

完成检索器修复后，对 Recall@5 失败题逐一分类：

- 相关知识不存在：属于语料覆盖问题。
- 相关内容存在但被切散：调整该类教材的标题继承、段落合并和 overlap。
- 内容与 OCR 混杂：修复清洗或重新解析对应页面。
- 内容完整但排序靠后：调整查询、BM25 token 或 reranking，不重切文档。

只有“存在但被切散”或“OCR 混杂”达到显著比例时，才启动针对性重建；重建前后必须复用同一标注集对比。

## 失败与降级

- BM25 全库缓存构建失败时，保留独立向量召回并记录降级原因。
- 向量服务不可用时，可以输出 BM25 候选用于检索评测，但不把 BM25 原始分数当作统一相似度。
- 两路均失败时返回空上下文，不注入低质量内容。
- 单条 embedding/rerank 失败时跳过该候选并记录，不使整卷中止。

## 测试与验收

实施采用测试驱动：先补失败测试，再改生产代码。

单元测试至少覆盖：

1. BM25 能召回不在向量候选中的相关文档。
2. RRF 只影响排序，不能单独让无关候选越过相关度阈值。
3. 查询构造保留公式、数值和单位。
4. OCR 过滤不会误删合理的公式密集片段。
5. 逐题预算能覆盖首题和末题，且总长度不超限。
6. BM25 缓存在集合数量变化时失效。
7. Chroma、BM25 或重评分单路异常时按设计降级。

验收顺序：

1. 新增测试先失败，实施后通过。
2. 运行物理标注集，要求 Recall@5 ≥ 80%，并审阅所有漏召回题。
3. 运行项目完整 `python -m pytest` 与 `python scripts/run_eval.py`。
4. 在相同模型、提示词、温度和试卷下重新执行无 RAG / 本地 RAG 对照，报告检索命中、实际注入和最终得分；不把随机分差直接归因于 RAG。

## 非目标

- 不接入 LLMWiki。
- 不修改联网搜索或原题答案搜索策略。
- 不把答案加入本地知识库或检索 query。
- 不实现图片 OCR、视觉模型或多模态答题。
- 不修改正式 Teacher Agent 的 Graph RAG、教学策略或数学判定器。
