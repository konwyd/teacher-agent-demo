# DeepSeek 风格对话界面与稳定会话上下文设计

## 目标

将 8502 的 LLM-led Teacher 页面改为接近 DeepSeek 的聊天界面，并从状态结构上消除以下故障：

- 点击“新建对话”后，页面重跑又跳回旧会话；
- 新问题被追加到旧对话，显示并携带不属于当前对话的上下文；
- 连续追问被保存到另一个会话，看起来像历史内容消失；
- 多个空记录都显示为“新对话”，无法辨认和选择；
- 学生 ID、RAG 状态等技术信息挤占主要聊天区域。

本次保留 Streamlit、现有模型调用、RAG、公开思考过程、验证详情、Token 与上下文容量功能，不重写 React/Vue 前端，不改变教学 Agent 和评测规则。

## 已确认的产品范围

### 页面布局

- 左侧栏顶部显示“开启新对话”按钮。
- 按“今天”“7 天内”“30 天内”“更早”分组显示已经有消息的历史对话。
- 当前会话在列表中高亮；点击某条历史记录即可切换。
- 不再使用现有的历史会话下拉框。
- 主区域只显示当前会话的消息。
- 用户消息靠右显示；公开思考过程和教师回答靠左显示。
- 底部保留输入框和当前已有的上下文容量显示。
- 学生 ID、RAG 状态、active problem、回合数等移入侧栏底部折叠的“调试详情”。
- 保留退出登录入口，但降低其视觉优先级。

### 新建对话

- 点击“开启新对话”只切换到一个内存中的空白草稿状态。
- 空白草稿不立即写入 SQLite，因此不会制造空的“新对话”历史项。
- 用户发送第一条消息时才创建真实会话记录。
- 新会话标题使用第一条学生消息，合并连续空白并截断到 80 个字符。
- 创建成功后，该会话 ID 成为唯一活动会话 ID；后续页面重跑不得改变它。

### 历史会话

- 历史列表只显示至少包含一条已完成回复或一条待重试学生消息的记录。
- 旧数据中残留的纯空会话不显示在界面上。
- 会话顺序按最后更新时间倒序。
- 标题为旧值“新对话”但已有消息时，界面使用第一条学生消息作为显示标题；后续保存时将标题修正为第一条学生消息。
- 切换历史记录前不创建新会话，也不改写被切换会话的数据。

## 会话状态模型

页面只保留一个权威活动目标：`prototype_conversation_id`。

- 其值为字符串时，`prototype_episode` 必须来自同一个数据库记录。
- 其值为 `None` 时，表示尚未落库的新对话草稿；此时 `prototype_episode` 必须为空。
- 历史列表控件不再通过独立的 `conversation_selector` 状态驱动会话，因此不存在两个会话 ID 相互覆盖的问题。
- 所有激活操作统一通过一个会话控制函数完成，同时更新活动 ID、episode、pending message、用户 ID 和 schema version。
- 退出登录时清理活动会话和草稿状态。

## 数据流与一致性保护

### 发送首条消息

1. 读取当前活动会话 ID；若为 `None`，创建会话并立即获得 ID。
2. 将学生消息写入该 ID 对应记录的 `pending_student_message`。
3. 将此 ID 保存为本轮不可变的 `target_conversation_id`。
4. 调用 Teacher Agent 生成回复。
5. 生成完成后，只允许把结果保存到 `target_conversation_id`。
6. 若活动 ID 与目标 ID 不一致，停止保存并显示明确错误，绝不写入另一个会话。

### 连续追问

1. 页面重跑保留活动会话 ID，不通过“最近更新记录”重新推断当前会话。
2. 每次发送都锁定当时的活动 ID。
3. 回答完成后继续停留在同一 ID，除非用户明确点击“开启新对话”或某条历史记录。

### 登录和热更新恢复

- 登录成功时恢复该用户最近更新的非空会话；若没有非空会话，则进入不落库的空白草稿。
- schema 热更新时优先保留当前活动会话 ID，并从数据库重新加载该 ID；不能调用“打开最近对话”覆盖当前选择。
- 若活动 ID 已不存在或不属于当前用户，则进入空白草稿并显示恢复提示，不选择任意旧会话。
- 待回复消息继续持久化，生成中断后仍提供“重新生成上一条消息”。

## 组件边界

### 会话展示语义

新增一个不依赖 Streamlit 的纯 Python 模块，负责：

- 从 episode 判断记录是否为空；
- 推导可靠的显示标题；
- 按更新时间生成“今天 / 7 天内 / 30 天内 / 更早”分组；
- 构建可以直接测试的历史列表项。

该模块不访问数据库、不读写 `session_state`，使显示规则可独立测试。

### Streamlit 会话控制

`streamlit_app.py` 负责：

- 新建空白草稿；
- 激活指定数据库记录；
- 渲染左侧历史按钮和当前项样式；
- 在发送前创建或锁定目标会话；
- 调用现有 `run_turn()`；
- 将技术信息放入“调试详情”。

### SQLite 存储

保留 `LocalConversationStore` 的按用户隔离规则，增加满足界面需要的最小能力：

- 列表层可过滤或跳过空会话；
- 保存时仍以 `user_id + conversation_id` 作为更新条件；
- 不提供模糊的“保存当前会话”全局行为，调用者必须传入明确目标 ID。

## DeepSeek 风格视觉规则

- 左侧栏使用浅灰背景、紧凑历史列表和圆角新建按钮。
- 当前历史项使用浅蓝背景，其他项悬停时才显示背景。
- 主内容限制最大阅读宽度并居中，减少整屏横向拉伸。
- 用户消息使用右对齐浅色气泡，教师回答使用无厚重外框的正文布局。
- “已思考”保持折叠面板形式，新完成的一轮首次展开，后续重跑折叠。
- 输入区固定在底部，保持现有上下文容量入口。
- 使用 Streamlit 原生控件和局部 CSS；不依赖不稳定的 DOM 文本选择器完成状态逻辑。

## 错误处理

- 创建会话失败：停止生成，保留输入并提示重试。
- 首次 pending message 保存失败：停止生成，避免用户消息只存在于内存。
- 生成失败：保留 pending message 和目标会话 ID，允许在同一会话重试。
- 最终历史保存失败：回答仍显示，但明确提示未保存；不得切换到其他会话。
- 切换加载失败：保留原活动会话，不显示目标会话的部分状态。
- 检测到活动 ID 与本轮目标 ID 不一致：中止持久化并显示“会话状态已变化，请重试”，不做猜测性恢复。

## 旧数据处理

用户已要求删除全部现有会话，只保留账号。该操作是一次性运维动作，不属于应用运行逻辑：

- 只清空 `data/runtime/conversations.sqlite3` 的 `conversations` 表；
- 不删除账号表、数据库文件、向量库、模型或学生档案；
- 应用启动时绝不自动清空历史；
- 当前环境的高风险命令审批额度已耗尽，因此该清理尚未执行。待审批恢复后执行，或由用户手动运行明确的清理命令。

## 测试与验收

自动化测试必须覆盖：

- 点击新建后，多次页面重跑仍停留在空白草稿；
- 新建草稿不产生 SQLite 空记录；
- 第一条消息创建新记录并自动命名；
- 第一条消息不会混入旧会话；
- 连续追问沿用同一会话 ID，并能看到此前消息；
- 切换历史后只加载目标会话的内容；
- 多个同名标题不会影响正确切换；
- schema 热更新不覆盖当前活动会话；
- 中断生成的消息仍保存在正确会话并可重试；
- 历史分组、排序、当前项高亮和技术信息折叠区存在；
- 思考过程、Token、验证详情和上下文容量显示继续工作。

完成前运行：

```bash
python3 -m pytest
TEACHER_FORCE_MOCK=1 python3 scripts/run_eval.py
```

验收标准：测试零失败，离线评测 38/38，通过真实页面操作验证“新建 → 首问 → 追问 → 切换 → 再切回”全过程无串台、无内容消失、无空历史记录。

## 非目标

- 不重写为 React、Vue 或其他独立前端。
- 不新增会话分享、搜索、重命名、删除单条历史等功能。
- 不改变 Teacher Agent 的提示词、教学策略、RAG 决策或确定性审计。
- 不展示模型私有逐字思维链。
