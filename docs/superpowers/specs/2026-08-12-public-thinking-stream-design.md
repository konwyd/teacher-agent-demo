# 8502 公开思考过程设计

日期：2026-08-12

## 目标

让 8502 LLM-led Teacher 在用户提交问题后，以接近主流大模型和 DeepSeek 的交互形式，实时展示可展开、可折叠的“思考过程”。展示内容来自真实 Agent 分类、工具调用、检索、验证和审计事件，但不是 DeepSeek 的原始 `reasoning_content`。

成功标准：

- 后端工作期间，思考区域随真实事件逐条更新；
- 完成后标题显示“已思考（用时 N 秒）”，并允许展开或折叠；
- 本次新回答的思考区域保持展开，后续历史回合默认折叠；
- 最终回答继续只展示经过现有确定性审计的文本；
- 页面刷新、重新登录和切换历史会话后仍能查看公开思考摘要；
- 不保存或展示原始思维链、系统提示、未经审计的初稿或其他敏感数据。

## 方案选择

采用“结构化公开思考流”，不直接美化技术日志，也不额外调用模型改写摘要。

每个真实运行事件经过白名单转换后形成面向用户的 `PublicThinkingEvent`。这种方案不增加模型调用和等待时间，展示内容与实际执行一致，并能在事件发生时立即更新。

不采用：

- 直接展示 `reasoning_content`：它可能包含杂乱、敏感或未经审计的内容，并会破坏当前安全边界；
- 回合结束后调用模型总结：增加成本和延迟，而且无法提供真实的实时过程；
- 原样展示 `AgentTraceEvent`：技术字段和调试措辞不适合作为学生可见产品界面。

## 总体架构

```text
Agent / RAG / verifier / audit
              │
              ▼
       PublicThinkingEvent
  类型、公开摘要、状态、耗时
              │
        ┌─────┴─────┐
        ▼           ▼
  实时思考区域    回合历史存档
        │
        ▼
“已思考（用时 N 秒）”
        │
        ▼
   审计后的最终回答
```

现有教学编排、RAG、数学 verifier 和最终回答审计仍是事实来源。新增转换层只负责生成公开事件，不改变业务决策。

## 公开事件契约

`PublicThinkingEvent` 是可序列化的稳定模型，至少包含：

- `sequence`：本回合内的严格递增顺序；
- `kind`：分类、教学策略、Skill、检索、验证、生成、审计、修正、完成或警告；
- `status`：进行中、完成或警告；
- `summary`：面向用户的简短中文摘要；
- `elapsed_seconds`：事件或阶段已有的耗时，没有可靠值时为零。

`PrototypeTurnRecord` 新增带空列表默认值的 `public_thinking_events`。旧会话缺少该字段时由 Pydantic 默认值兼容加载。

公开事件转换只能读取白名单数据：

- 学科、学段、新题或追问；
- 已加载的教学 Skill 名称；
- 本地或联网检索状态和命中数量；
- verifier 是否执行以及公开状态；
- 最终审计和修正结果；
- 阶段耗时。

转换器不得读取或复制：

- `reasoning_content` 或其他原始思维链字段；
- system prompt、完整模型输入或 API 密钥；
- 未经审计的教师初稿；
- 完整 RAG 文本；
- 异常堆栈；
- Agent 决策对象中未经白名单约束的自由文本或 `details` 全量内容。

## 数据流

`run_turn()` 继续通过已有进度回调报告稳定阶段和 `AgentTraceEvent`。新增独立的公开事件构建器负责：

1. 接收阶段或 Agent 事件；
2. 根据事件类型和白名单字段生成 `PublicThinkingEvent`；
3. 立即把事件交给 Streamlit 渲染；
4. 在回合结束时把完整公开事件列表写入 `PrototypeTurnRecord`。

分类、Skill、检索等事件来自 bounded Agent Loop。学生步骤验证、生成、审计、修正和完成事件由 `run_turn()` 在真实边界处补充，避免仅靠页面猜测后台状态。

“思考用时”定义为从收到学生问题到最终审计完成的 `backend_total_seconds`，不包含审计后答案逐字展示时间，也不包含用户阅读时间。

## 页面交互

当前回合在 assistant 消息区域内先创建思考状态框：

- 运行时标题为“🧠 思考中…（已用时 N 秒）”；
- 框内按照事件顺序追加公开摘要；
- 完成后标题改为“🧠 已思考（用时 N 秒）”；
- 新生成回合保持展开，用户可手动折叠；
- 最终回答紧接在思考区域下方；
- Tokens 和“验证详情”继续保留在最终回答之后。

历史消息使用 `st.expander` 渲染已保存事件，默认折叠。生成结束后的现有 `st.rerun()` 通过一个临时 session-state turn id 识别刚生成回合：该次重绘保持展开，下一次用户交互后恢复历史默认折叠。

事件正文采用简短步骤，而不是调试日志。例如：

- “正在识别题目和学生意图……”；
- “已确定为初中数学新题。”；
- “正在检索相关教材与例题……”；
- “找到 4 条可用参考。”；
- “当前题型暂无确定性验证，回答将保留不确定性说明。”；
- “最终回答通过教学节奏与内容审计。”

页面不得显示 `Agent 1`、内部工具参数、完整分类 JSON 或原始异常信息。

## 异常处理

- 分类失败：公开显示已切换到安全教学模式，继续现有降级流程；
- 本地检索失败：显示警告，并由现有规则决定是否允许联网；
- 联网失败：显示联网参考不可用，继续使用已有证据；
- verifier 不支持：明确显示暂无确定性验证，不伪装成验证通过；
- 初稿触发修正：只显示发现风险并正在修正，不显示违规初稿；
- 整轮生成失败：实时思考框进入失败状态，保留学生消息和重新生成入口；
- UI 回调或公开事件渲染失败：不得阻断 Agent 和最终回答；
- 历史保存失败：最终回答仍显示，并沿用现有保存警告。

## 测试与验证

离线测试至少覆盖：

1. 阶段和 Agent 事件按真实顺序映射为公开事件；
2. 分类、检索、verifier、审计和修正的公开摘要与实际状态一致；
3. `reasoning_content`、prompt、草稿、完整 `details` 和敏感值无法进入公开事件；
4. 回调失败不阻断教学回合；
5. 新回合保存公开事件，旧回合缺少字段时仍能加载；
6. 当前回合展开、历史回合折叠，空事件历史不渲染空框；
7. 后端总耗时和标题展示一致；
8. 失败与降级路径使用警告状态，不误报成功；
9. 最终回答仍在 `run_turn()` 返回、审计完成之后才显示。

完成后运行：

```bash
python3 -m pytest
TEACHER_FORCE_MOCK=1 python3 scripts/run_eval.py
```

## 非目标

- 不修改模型、temperature、上下文窗口或推理预算；
- 不保存或展示 DeepSeek 原始 `reasoning_content`；
- 不改变 RAG、联网触发、数学 checker、教师 prompt 或审计规则；
- 不把公开思考摘要发送回模型作为后续上下文；
- 不重构 Streamlit 页面、认证或会话存档系统；
- 不修改旧 8501 页面。
