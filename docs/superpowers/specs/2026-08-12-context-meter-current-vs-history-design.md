# 上下文占用：当前配置与历史记录分离设计

## 目标

上下文组件必须稳定表达当前模型服务的容量，并避免把旧对话保存的历史配置误认为当前上限。

## 展示规则

- 收起状态显示“本轮最后一次模型请求占用 / 当前模型上限”及其百分比。
- 当前模型上限只读取本次 Streamlit 启动环境中的 `DEEPSEEK_CONTEXT_WINDOW_TOKENS`。
- 本轮占用继续读取当前对话最后一轮的 `context_used_tokens`；没有模型请求时显示 0。
- 展开状态分别列出：本轮请求占用、当前模型上限、该对话记录的历史上限。
- 历史上限与当前上限不一致时，明确标注为“旧配置记录”，不得参与主百分比计算。
- 文案说明该数值是最近一次请求，而不是整段对话累计 token，也不是显存占用。

## 数据流

1. 启动器把实际 `--ctx-size` 写入 `DEEPSEEK_CONTEXT_WINDOW_TOKENS`。
2. 页面以该环境变量作为唯一的当前容量来源。
3. 对话轮次元数据只提供最近请求的占用和历史容量，用于详情与诊断。
4. 主百分比使用 `最近请求占用 / 当前容量`，并把进度条限制在 0–100%。

## 兼容性

- 不迁移或覆盖已有对话数据。
- 老对话缺少上下文元数据时，历史上限显示“暂无记录”。
- 若历史占用超过当前上限，仍显示原始占用值，同时以超过 100% 的文字百分比提示配置已经变化；进度条仅作满格显示。

## 验证

- 单元测试覆盖历史上限为 512K、当前上限为 128K 时，主显示必须采用 128K。
- 单元测试覆盖历史详情保留 512K 并带旧配置标记。
- Streamlit UI 回归测试确认切换旧、新对话不会改变当前模型上限。
- 运行完整测试和离线教学评测。
